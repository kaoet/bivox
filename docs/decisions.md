# 设计决策

本文件记录 kaols 当前生效的设计决定及其理由。

- `D??` 是**稳定的决策编号**，源码注释与 [architecture.md](./architecture.md) 会引用；新增决定使用新编号，推翻旧决定时保留编号并注明被哪一条取代。
- 只记录“现在的结论与原因”，不记录实施进度、里程碑或历史版本。
- “怎么做”的模块与算法细节见 [architecture.md](./architecture.md)；用户可见行为以 `README.md` 为准；开发流程与编码规范见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

---

## D1 GUI 框架：egui + eframe 0.37.0，版本钉死

**决定**

- 使用 `eframe = "=0.37.0"`（egui 系列同版本），API 以 <https://docs.rs/eframe/0.37.0/> 为准。
- `eframe::App` 的绘制方法是 `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`；**不使用**旧版 `fn update(&mut self, ctx: &egui::Context, ...)`。
- 渲染后端用 Cargo feature 二选一：`renderer-wgpu`（默认）/ `renderer-glow`；两者都不启用时在 `src/lib.rs` 用 `compile_error!` 阻止编译。
- 启用 `default_fonts`、`system_fonts`、`accesskit`、`clipboard`、`links`、`inspection`；**不启用** `persistence`。

**理由**

- 纯 Rust、单 exe、无运行时依赖；立即模式适合“控制面板 + 字幕 + 日志”这类工具。
- `inspection` 让开发期和 AI agent 可以通过 egui_mcp 观察并操作真实界面。
- `persistence` 默认把窗口状态写进系统配置目录，与便携模式冲突。

**边界**

- 升级 eframe/egui 必须整体升级，并重新验证绘制签名、截图/调试行为与本文其它决定。

## D2 交付形态：单二进制、便携、无安装器

**决定**

- 发布物只有一个 `kaols.exe`；zip 只含 `kaols.exe` + `README.md`。
- **不**打包 `config.toml`、`config.example.toml`、`voice_cache.json`、日志、调试工具。
- 升级方式：覆盖 exe 与 README，旁边的配置/缓存/日志保持不动。
- release 构建不弹控制台（`windows_subsystem = "windows"`），debug 保留控制台便于排错。
- exe 文件图标由 `build.rs` + `assets/kaols.ico` 嵌入；窗口图标在 `src/app.rs` 程序化生成（不引入图片解码依赖）。

**理由**

- 无需安装器、无需管理员权限；目录整体拷贝即迁移。
- 避免把开发机密钥带进发布包。

## D3 配置模型与写回范围

**决定**

- `config.toml` 是唯一配置事实源，GUI 不引入第二种配置格式。
- **GUI 只能修改以下字段**：
  1. `[api] key`
  2. `[audio] input_device` / `output_device`
  3. `[tts] voice`
  4. `[tts.custom_voices]` 整个结构
  5. `[translate] enabled` / `target` / `granularity` / `show_source`（D25/D26；`model` 仍只读）
- 其余字段（`[asr]`、`[tts] model`、`[tts] cache_file`、`[vad]`、`[chunking]`、`[api] workspace_host` 等）只读：设置页展示当前值，用户手改后点「重新加载配置」。
- 写回流程：读原文本 → 用 `toml_edit` 定点修改 → 用 `AppConfig::from_toml_str` 校验整份新文本 → 备份 `config.toml.bak` → 写盘。没有实际改动时不写盘、不产生备份；校验失败不落盘。
- API Key 以**明文**保存在 `config.toml`；界面与 README 都提示该文件含密钥、勿分享。

**已知限制**

- 整体重写 `[tts.custom_voices]` 时，该表**内部**的注释会丢失；表外注释保留。v1 接受。

**理由**

- 保留用户手写的注释、字段顺序与格式；单事实源避免 GUI 与文件两份配置漂移。
- 写前校验 + 备份把“写坏配置”的风险降到最低。

## D4 便携路径：所有可写文件都在 exe 同目录

**决定**

- 配置、缓存、日志、崩溃记录全部位于 `<exe 目录>`：

  ```text
  kaols.exe
  config.toml            # 首次启动生成
  config.toml.bak        # GUI 每次写回前备份
  voice_cache.json       # 自定义音色缓存（默认相对 config.toml 所在目录）
  logs/kaols-YYYY-MM-DD.log
  crash.log
  ```

- 主程序**不读** `%APPDATA%`、注册表、当前工作目录，也不通过环境变量改变配置/路径。
- 配置里的相对路径（缓存文件、样例音频）以 **`config.toml` 所在目录**为基准。
- 唯一的环境变量例外：`EGUI_INSPECTION=1` 仅开启调试 inspection 端口，不改变任何配置或路径语义。
- 开发期 `cargo run` 的 exe 在 `target\<profile>\`，用 `scripts/dev-run.ps1` 把仓库根 `config.toml` 复制过去，并把副本的 `[tts] cache_file` 指向仓库根 `voice_cache.json`；不使用 symlink（Windows symlink 需额外权限，且缓存的“临时文件 + rename”原子写会替换链接本身）。
- 仅支持 Windows 10/11 x64。

**理由**

- 便携目录可整体备份、拷贝、迁移；备份目录即备份密钥与音色缓存（README 明确提示风险）。

## D5 线程模型：eframe 占主线程，tokio 跑在后台

**决定**

- `main` 创建多线程 tokio Runtime 并持有（不用 `#[tokio::main]` 包住 GUI 主线程），把运行时句柄存进应用状态；后台任务通过 `runtime.spawn` 启动。
- UI 线程只做绘制与状态更新：**禁止**在 UI 线程 `await`、阻塞读文件、做网络请求。
- cpal 音频回调线程只做混音/重采样与 `try_send`；通道满时丢弃优于卡顿。
- 停止通过 `Arc<AtomicBool>` 标志传递（不引入 `tokio-util` 取消令牌）。

**理由**

- eframe 必须占用主线程；实时音频回调不能等待锁或异步运行时。

## D6 事件总线：`PipelineEvent` + 无界通道 + `request_repaint`

**决定**

- 后台 → 界面统一走 `tokio::sync::mpsc::unbounded_channel::<PipelineEvent>()`；后台每次发事件后调用 `ctx.request_repaint()`，界面每帧 `try_recv()` 排空。
- 事件里不出现 egui 类型，保持可测试；字段以 `src/events.rs` 为唯一事实源：
  `StateChanged`、`Devices`、`VoiceInfo`、`Asr { text, is_sentence_end, sent_bytes, language, sentence_id }`、`TypedSentence`、`VadActive`、`Error`。
- 反向命令（GUI → 会话）同样走通道：`PipelineSessionHandle` 持有打字输入的无界 `Sender`，会话调度循环用 `biased` select 优先处理它（D24）。
- 管线内部（音频、ASR 事件、TTS 输入）使用有界 channel（容量 100）；音频回调用 `try_send`，满即丢包。

**理由**

- UI 与后台解耦、可单测；由事件驱动重绘，避免每帧轮询睡眠。
- 内部有界通道防止某一侧卡住时内存无限增长；音频丢包是实时场景可接受的降级。

**约束**

- 新增事件变体时，必须同时更新 `events.rs`、`app.rs` 的事件处理、本文件与架构文档。

## D7 日志体系：`log` 门面 + 内存环形缓冲 + 按天文件

**决定**

- 引入 `log`，自写 `LogSink`（不引入 tracing），同时写入：
  1. 内存环形缓冲：上限 5000 行，供界面日志面板消费；
  2. `<exe 目录>\logs\kaols-YYYY-MM-DD.log`：按天追加，保留最近 7 天（启动时清理更早的按天日志）。
- 写日志前剥离 ANSI 颜色码（`colored` 仅用于调试 CLI 的终端输出）。
- 安装 panic 钩子：写 `crash.log`（含 backtrace）并把信息交给界面顶部红色错误条。
- 库代码不使用 `println!`/`eprintln!`；仅调试 CLI 与启动前的极端基础设施错误走 stderr。
- 界面日志面板使用等宽字体、按级别着色，渲染最近 500 行；面板高度可拖拽（默认 180px，最小 60px）。

**理由**

- release 无控制台，日志是唯一可持久化的诊断线索；便携目录内落盘无需额外权限。

## D8 错误与崩溃必须可见

**决定**

- 用户可感知的错误不得静默：转成 `PipelineEvent::Error`，在界面顶部显示红色错误条（可手动清除），同时 `log::error!`。
- 配置写回失败在对应页面内显示；配置无效时在设置页展示错误链并禁止启动实时会话。
- 写默认配置、日志初始化等基础设施失败属于启动阶段的非致命错误：显示启动横幅 `startup_error`，界面照常打开。
- 用户主动停止/关窗不弹错误；后台 ASR/TTS 服务非用户主动退出时才上报“服务异常退出”。
- 崩溃通过 panic 钩子写 `crash.log`，并在下一帧以错误条展示。

**编码约定**

- `let _ =` 只能用于“忽略失败是正确的”路径，且需要原因注释；具体约束见 [CONTRIBUTING.md](../CONTRIBUTING.md) 第 6 节，本文只保留设计原则：**任何用户可感知的失败都必须有可见出口**。

**理由**

- 没有控制台时 stderr 不可见；可感知的错误必须出现在用户会看到的地方。

## D9 渲染后端：默认 wgpu（DX12），glow 作为截图/兜底变体

**决定**

- 默认构建启用 `renderer-wgpu`（DX12）。
- `--no-default-features --features renderer-glow` 产出 OpenGL 变体，用于：
  1. 静态截图核对：`EFRAME_SCREENSHOT_TO` 只在 glow 路径实现（wgpu 上游未实现）；
  2. 某些机器/远程桌面下 DX12 初始化失败时的兜底。
- 截图构建还需开启 `eframe/__screenshot`，并要求窗口可见；`egui::Grid` 等会触发 multi-pass 的组件可能截到空帧，需要截图的页面避免使用。

**理由**

- 默认使用现代后端；OpenGL 保留为可验证、可兜底的构建变体。

## D10 字体：不打包字体，依赖系统字体

**决定**

- 不随程序打包字体文件；依赖 egui 0.37 的 `system_fonts` 从 Windows 系统字体按需加载中文与彩色 emoji。
- 个别字体缺失的机器，可临时手动注册 `C:\Windows\Fonts\msyh.ttc`（TTC 取 0 号字面）。

**理由**

- 减小体积、避免字体许可问题；现代 Windows 上开箱可用。

---

## D11 音色管理：GUI 只编辑配置，运行期负责复刻与缓存

**决定**

- GUI「语音合成」页只编辑 `config.toml` 中的 `[tts] voice` 与 `[tts.custom_voices]`：**不发任何网络请求、不读写 `voice_cache.json`**。
- 真正生效发生在会话启动时：`voice::resolve_active_voice` 解析 `[tts] voice`：
  - 内置音色 / 任意 voice_id：原样使用，不访问网络；
  - `custom:<键名>`：逐样本读取音频 → 计算 SHA256 → 查本地缓存 → 校验云端是否仍存在 → 未命中或已失效则上传样例音频、创建复刻音色、轮询到就绪 → 写回缓存。
- `voice_cache.json` 由运行期维护；GUI 删除音色配置后留下的孤儿缓存条目无害，不提供清理入口。
- 远程音色的列出/删除只走 `admin` 调试 CLI（D19）。
- 自定义音色样本是**有序数组**，`samples[0]` 是默认声线；合成时按本句语言选样本，缺该语言回退第一个样本。

**理由**

- 配置编辑与远程状态解耦：GUI 不阻塞、不并发写缓存；打开程序不等于访问网络。

## D12 设备枚举与精确匹配

**决定**

- GUI 下拉框保存**完整设备名**；空值表示系统默认设备。
- 查找时按完整名称**精确相等**匹配：不做大小写模糊、不做子串匹配、不静默回退默认设备；找不到时明确报错并提示用户在「音频」页重选。
- 设备列表只在启动与点「刷新设备」时枚举，不做热插拔监听。

**理由**

- 用错设备（尤其是虚拟声卡/麦克风）比明确报错更难排查。

## D13 优雅退出：先停管线再关窗

**决定**

- 收到关闭请求后先 `CancelClose`，请求停止实时管线（置停止标志），等后台任务收尾，再在下一帧真正 `Close`。
- 会话任务退出前：drop 音频采集（释放麦克风）、关闭 TTS 输入通道、等待 ASR/TTS 任务最多 3s、drop 播放引擎（释放扬声器）。
- GUI 不持有 cpal `Stream`，只持有 `PipelineSessionHandle`；正常停止以 `StateChanged(Idle)` 结束，失败由外层转成 `Failed` + `Error`。

**理由**

- 保证设备释放，避免退出后麦克风/扬声器仍被占用或进程卡住。

---

## D14 可测试性：核心逻辑纯函数 + egui_mcp 手工回归

**决定**

- **不接入 `egui_kittest`**：真实 UI 与音频设备、网络管线耦合，为每个用例 mock 的成本高于收益。
- 核心逻辑用模块内单测覆盖：配置解析/校验、`config_edit` TOML 改写、音色草稿、字幕 reducer、语言判定、分块、协议解析、缓存等。
- WebSocket 协议测试在测试代码内用本地 `TcpListener` mock；HTTP 接口测试用 `src/voice/mock_http.rs` 的手写 mock 服务；不依赖真实百炼网络。
- UI 回归用 `EGUI_INSPECTION=1` + egui_mcp 真实点击/截图核对；发布前再做人工冒烟（开始/停止、配置保存、双开单实例、release 启动）。

**理由**

- 以低成本覆盖高价值、易回归的纯逻辑；UI 用真实运行期观测而非脆弱的假界面。

## D15 依赖与版本策略

**决定**

- `eframe`/`egui` 固定为 `=0.37.0`，不自动跨小版本升级；`Cargo.lock` 提交。
- Rust 版本受 egui 0.37 约束（MSRV ≥ 1.95）；当前开发工具链为 rustc 1.99.1。
- `cpal` 固定 0.18：设备名走 `description()?.name()`、采样率返回 `u32`、`build_*_stream` 接收 `StreamConfig` 值；同时避免旧版 `windows` crate 与 wgpu DX12 的版本冲突。
- 升级任何 GUI/音频/网络依赖时，必须同时验证构建、测试与 GUI 冒烟，而不是只改版本号。

**理由**

- 模型/教程里 eframe 旧 API 与旧 cpal 代码很多，钉版本能避免错误样例被引入。

## D16 字幕与日志留存

**决定**

- 日志内存上限 5000 行（界面渲染最近 500 行）；字幕历史上限 500 句；均为环形裁剪、丢最旧。
- 字幕只支持**单句复制**，不提供复制全部/导出；不保存历史会话到磁盘。
- 实时页：当前正在合成的句子在最上面，历史句越早越靠下；顶部对齐；不分段、无标题；字号 24px；行间分隔线。
- 每行最左固定 24px 显示本句语言代码（当前句在判定前显示 `…`），语言列必须等于该句 **TTS task 首个 chunk 实际使用的语言**，保证显示与实际合成一致。
- 当前句按 TTS 进度分色：已送入 TTS 的前缀用正常色，尚未送入的部分用弱色（正常色 ×0.45）；当前句不显示复制按钮。历史句在鼠标悬停整行时于行尾显示复制图标。
- 历史句去重按服务端 `sentence_id`：同一句重复下发最终结果只记一次；两次真实发音即使文本相同（id 不同）也各自保留。空文本 + 句终是 ASR 的“重置信号”。
- 停止或重新开始会话时**只清当前句**，历史保留。

**理由**

- 低延迟场景下字幕需要稳定可读；按 sentence_id 去重能避免把重复的两个真实句子合并。

## D17 启动、窗口与实例行为

**决定**

- 启动后不自动监听，初始状态 `Idle`；用户点「开始」才申请麦克风等设备。
- 窗口状态不持久化：每次启动回到默认 1100×720、居中；可自由调整，退出不保存。
- 单实例：用命名 Mutex（`Local\kaols-<exe 路径哈希>`）限制同一目录只能有一个实例；第二个实例尝试恢复并置前已有窗口后退出。不同目录的两份便携副本可以同时运行。
- 不做托盘图标、不做全局热键。

**理由**

- 避免重复启动抢麦克风；不同便携副本互不影响。

---

## D18 首次运行

**决定**

- 启动时若 `<exe 目录>\config.toml` 不存在：写入编译期内嵌的默认模板（`config.example.toml`，其中 `[api] key` 保持注释状态），并落在「设置」页引导填写 Key。
- 配置存在但解析/校验失败：同样落在「设置」页，展示错误链，不直接退出。
- `config.example.toml` 是模板的**唯一事实源**（`include_str!` 编进 exe）；发布包不再附带该文件。
- 启动阶段的非致命错误（写默认配置失败、日志初始化失败等）记录为启动横幅 `startup_error`，界面照常打开。

**理由**

- 首次运行必须“打开就能看到下一步做什么”，且错误可见。

---

## D19 独立调试 CLI：`admin`

**决定**

- 独立二进制 `admin`，只做三件事：列出账号下的自定义音色、删除指定 voice_id、删除全部音色。
- 凭据来源：默认读**当前工作目录**的 `./config.toml`，可用 `-c/--config <path>` 指定；沿用同一套配置校验，只实际使用 `[api] key` 与 `[api] workspace_host`。
- **不读写 `voice_cache.json`、不提供 enroll（上传/复刻）、不做任何 prefix 过滤**；只按 voice_id 精确操作。
- 逻辑放在 `src/voice/admin.rs`（可用 mock HTTP 单测），bin 只做参数解析与终端输出。
- 不随发布包分发。

**缓存与远程删除的关系**

- 若远程 voice_id 被删除，下次会话启动解析自定义音色时，`query_voice` 会将其判定为不存在并自动重新复刻；网络错误时则先沿用缓存（标记为未校验）。一般无需手工删除 `voice_cache.json`。

**理由**

- 与 GUI 的边界清晰（GUI 不碰远程与缓存），调试工具保持“哑”且可测试。

## D20 运行中配置热更新：自动重启实时管线

**决定**

- GUI 写回配置成功或点「重新加载配置」后，若会话处于 `Starting`/`Running` 且“运行时配置指纹”发生变化：
  1. 标记 `restart_pending`，调用 `stop_session()` 让旧会话收尾；
  2. 收到旧会话的 `StateChanged(Idle)` 后，用新配置自动 `start_session()`。
- `Stopping`/`Idle`/`Failed` 不触发自动重启；关窗时清除 pending；重启失败只报一次错，不自动重试（避免坏配置/不可用设备形成重启循环）。
- 指纹必须**顺序稳定**：手工拼接会影响运行的字段，自定义音色按配置名排序；不能直接 `format!("{config:?}")`（`HashMap` 的 Debug 顺序随实例随机，会导致每次保存都误判为变化）。

**理由**

- 用户改 Key/设备/音色后立即生效，不必手动停止再开始；同时避免误判和重启风暴。

## D23 自定义音色样本语速（rate）

**决定**

- `[[tts.custom_voices.<键名>.samples]]` 增加可选字段 `rate`（f32），对应 Qwen-Audio-TTS run-task 的 `rate` 参数：默认 `1.0`，有效范围 `[0.5, 2.0]`。
- 语速属于**样本**而不是音色：同一音色不同语言的声线可以各自设置语速。
- 合成时按本句语言选中的样本决定 `rate`；缺该语言回退第一个样本时，使用回退样本的 `rate`；内置音色/普通 voice_id 固定 `1.0`。
- `rate` 只影响合成请求参数，**不参与复刻与缓存键**：修改语速不会重新上传/复刻样例音频，缓存命中不变。
- GUI 在自定义音色编辑器中为每个样本提供「语速」滑条（0.5–2.0，步长 0.05）与「重置」，随 Tab 级「保存」写回；运行中保存按 D20 热重启。
- 配置校验拒绝非有限（NaN/∞）或越界（<0.5 或 >2.0）的 `rate`。

**理由**

- 不同语言的复刻声线本身语速未必合适；把语速绑定到样本，可以分别校正，且不改变音色与缓存语义。

## D24 实时页「打字输入」：排队朗读，不打断播放

**决定**

- 「实时」页字幕区下方提供输入框（支持多行，Shift+Enter 换行）；按 Enter 或点「朗读」把输入内容交给当前实时会话排队朗读（下称**打字输入**）。
- 只有会话处于 `Running` 时可提交；未运行时输入框仍可输入，提交时给行内提示。空白不提交；单次输入上限 **500 字符**（界面校验；会话侧对异常调用的超长文本按字符边界防御性截断并记 warning，不整句丢弃）。输入框默认 1 行，约 4 行封顶后内部滚动。
- 打字输入句的合成方式：
  1. 作为**独立的新 TTS task**：整句一条 `continue-task` + `finish-task`，不经过流式分块；
  2. 语言判定与 ASR 共用**同一个** `LanguageTracker`（继承当前对话的粘性语言，并把判定结果回写 `current`）；voice / rate / instruction 按该语言解析（与 ASR 句相同）；
  3. 提交即进字幕历史（不按 `sentence_id` 去重、不额外标记来源）。
- 插入语义：
  - **不打断、不清空播放队列、不取消 TTS task**：已排队/正在播放的音频照常播完，打字输入句排在队尾（FIFO）。
  - 若 ASR 当前句的 TTS task 还开着（已送 chunk、未发句终），先发「空文本 + 句终」让它正常收口（已收到的文本合成完、音频继续入队），再发打字输入句作为下一个 task。
  - 若 ASR 当前句尚未识别结束：把当前字幕句按**已送 TTS 的字节前缀**收尾进历史（前缀为空则直接清空当前行），重置本地分块与句状态，并丢弃该句剩余部分直到服务端给出句子结束；期间不再送 TTS。
- 不引入第二 TTS 模型或第二协议，沿用 `[tts] model`（D3）。
- GUI 回车用「多行输入框保持焦点」语义：`TextEdit::multiline` 的 `return_key` 设为 **Shift+Enter**（原生插入换行），单独 Enter 由界面检测后提交；中文 IME 确认候选的 Enter 由 egui-winit 的 `VK_PROCESSKEY` 过滤保证不会提交。

**理由**

- 播放队列是 FIFO，排队语义符合“不要打断当前朗读”的预期；在任务边界处排队，避免把打字文本拼进 ASR 当前句、也避免打断正在播放的音频。
- 打字输入与语音输入同属一段对话，语言粘性应共享，否则“日语句子中间打‘东京’却按中文读”会违背用户意图。
- 不取消 task、不清播放队列后，TTS 客户端与播放层无需改动，行为风险最低。

**边界**

- 打字输入句的语言仍受 `[asr] languages` 约束（与 ASR 相同），列表外的语言回退到列表首个。
- 排队期间停止或热重启会话时，尚未播放的打字输入句随会话丢弃，字幕历史保留。
- 被打断的 ASR 句剩余部分不会补读；字幕只保留已送 TTS 的前缀。

## D25 翻译模式：ASR/打字 → MT → 现有 TTS

**决定**

- 翻译模式作为现有实时管线的**中间层**：源文分块后逐块调用 `qwen-mt-flash`（OpenAI 兼容 HTTP），译文再走现有 TTS、播放与字幕；不引入第二套实时语音协议，也不改播放层。
- 目标语言限 **16 种** TTS 官方支持语言（`TRANSLATION_LANGUAGES = CLONING_LANGUAGES`），默认 `en`；翻译模型默认 `qwen-mt-flash`。请求必须带 `translation_options = { source_lang, target_lang }`（缺失会退化成普通对话模型）；源语言直接用 ISO 代码，无法判定时用 `auto`。
- 配置放 `[translate]`（`enabled` / `target` / `model` / `granularity` / `show_source`）：M1 只读配置、字幕只显示译文（双语字幕由 D26 细化）；独立 GUI 翻译页由 M3 提供（D27）。
- 分块：默认 `clause` = 标点/句终切，且标点切点必须离开 ASR 尾部 ≥3 字符；可选 `sentence` = 只句终切。默认 `ChunkPolicy` 与现有 TTS 路径行为完全不变。
- 翻译 worker 独立 tokio 任务、单 in-flight 保序；打字输入 bump `generation` 丢弃旧句在途译文；源文句终用「等 `pending` 归零再 finish-task」的屏障。
- 源语言 == 目标语言时跳过 MT，直接送 TTS。
- 翻译失败按 D8 显示错误条，失败片段不送 TTS；已送 TTS 的译文不可撤回，也不重试已送内容。

**理由**

- 复用现有 ASR/TTS/播放/音色/字幕与打字输入，改动面最小；spike 实测 `qwen-mt-flash` 短句 0.2–0.3s、16 语种全部可用，端到端延迟可控。
- LiveTranslate 一体模型延迟更低，但不支持打字输入、音色需按该模型另建、RPM 仅 10，无法覆盖现有打字输入与自定义音色路径。
- 字幕只显示译文可保证“看到的字幕 = 听到的音频”，避免原文/译文错位。

**边界**

- M1 无 GUI 开关；启用或改目标语言需手改 `config.toml` 后「重新加载配置」。M2 起字幕支持双语（D26）；M3 起有独立「翻译」页（D27）。
- 已送 TTS 的译文不能撤回；`clause` 模式每个标点最多多等一次 ASR 更新（约 100–300ms）。
- 自定义音色缺目标语言样本时按 D11 的样本回退规则处理，不额外提示。
- 翻译逐块 HTTP，不做跨句上下文；长文连贯性依赖模型自身。

## D26 翻译模式 M2：双语字幕与逐行复制

**决定**

- 翻译模式下一"条"字幕由两行组成：**译文大字行**（24pt）在上、**原文小字行**（15pt，弱色）在下；两行各自有语言列（译文行=目标语言，原文行=源语言）。`show_source = false` 时只渲染译文行，行为与 M1 相同。
- 字幕 reducer（`app::SubtitleState`）在 `translation_mode` 下拆成两个纯函数：`apply_source`（只刷新原文与「已送翻译」前缀，不句终）与 `apply_translation`（累积译文；句终时把「原文 + 译文」作为一条历史记录落库；同一 `sentence_id` 去重；空译文句终只清当前行、不落历史）。
- 事件契约：翻译模式下 `PipelineEvent::Asr` 的 `sent_bytes` = 已送翻译的**源文**字节长度、`is_sentence_end` 恒为 `false`、`language` = 源语言；句终与当前行收口由 `PipelineEvent::Translation` 负责（其 `sent_bytes` = 已送 TTS 的**译文**字节长度）。非翻译模式下 `Asr` 语义与行为不变。
- 原文行与译文行**各自**可复制：悬停对应行时该行右端显示复制图标，复制的是该行完整文本（原文行复制源文、译文行复制译文）。
- `show_source` **不进**配置指纹：修改后「重新加载配置」即时改变渲染，不重启会话；`enabled/target/model/granularity` 进指纹，运行中变更按 D20 热重启。

**理由**

- 双语字幕让用户同时对照源文与译文，而「听到什么」仍以译文行为准；逐行复制便于引用与校对，也避免整条一起复制导致两种语言混在一段文本里。
- 复用同一套字幕状态机（而不是原文/译文两条并行历史），历史上限、去重、停止清空等既有语义保持一致。
- `Asr` 事件在翻译模式下只承担「当前原文进度」，把句终交给 `Translation` 可以让"译文失败也要收口当前行"成为一条明确规则。

**边界**

- M2 仍没有独立 GUI 翻译页（M3 已补，D27）；启用或改目标语言在 M2 需手改 `config.toml` 后「重新加载配置」。
- 原文行是辅助信息：若整句译文全部失败，当前原文行在句终时被清空，不落历史（与"字幕 = 听到的内容"一致）。
- 语言列宽固定 32pt，以容纳 `fil` 这类三字母代码。

## D27 翻译模式 M3：独立「翻译」页与配置写回范围

**决定**

- 新增独立「翻译」页（`Tab::Translate`，`src/gui/translate_tab.rs`），所有翻译选项集中于此；顶栏工具栏不新增翻译开关，保持现状。
- GUI 可写 `[translate] enabled` / `target` / `granularity` / `show_source`（D3 白名单扩展），`model` 只读展示。写回统一走 `config_edit::set_translate` + 现有「校验 → `.bak` → 写盘」流程；未启用翻译时目标语言与粒度控件禁用，`show_source` 仍可改。
- 改值即保存：`show_source` 不进配置指纹，重载后立即改变渲染、**不重启**；`enabled` / `target` / `granularity` / `model` 进指纹，运行中变更按 D20「停旧会话 → 用新配置自动重启」，当前句会丢失（页内注明）。
- 空闲时改配置只影响下次开始；`reload_config` 在会话未运行时把 `SubtitleState::translation_mode` 同步为新配置，空状态提示与后续渲染一致。运行中则仍由 `start_session` 在重启后设置。

**理由**

- 用户不必手改 `config.toml` 即可完成开关与目标语言选择；独立页避免实时页被设置项占据。
- 复用 D3 定点写回与 D20 热重启，没有引入新的配置或生命周期机制；`show_source` 只影响渲染，热加载不中断会话。

**边界**

- 目标语言下拉固定 16 种（`TRANSLATION_LANGUAGES`，与 TTS 音色语言一致）；不在列表内的代码即使手改配置，`enabled = true` 时也会被校验拒绝。
- 更换 `model` 仍需手改配置并「重新加载配置」（只读展示）。
- 热重启会丢当前句，与其它 GUI 配置改动一致。

## D28 翻译模式：句终屏障期间缓存下一句的 ASR 事件

**决定**

- 翻译模式下，源文句终（`is_sentence_end`）时若还有译文在途，进入「句终屏障」：先不发下一句的源文事件、也不把下一句的 chunk 送翻译 worker，而是把到达的 ASR 事件按序放进 `asr_backlog`。
- 等最后一条译文返回、旧句句终 `Translation` 事件发出并复位本句状态后，主循环按原顺序补处理缓存事件，再继续正常收 ASR。
- 打字输入在屏障期间到达时，清空缓存并沿用 D24 的「丢弃当前 ASR 句剩余事件」规则（把缓存里刚开始的新句一并丢掉）。

**理由**

- 界面（D26）按「当前原文 + 累计译文」配对：如果下一句的源文先落到界面、旧句句终译文后到，就会把新句原文和旧句译文配成一行，表现为「一句话出现两句、原文译文错位」。
- 屏障期间若继续处理下一句并送翻译，`pending` 会计入新句的译文任务，旧句句终事件会被推迟到新句译文全部返回之后，且 `runtime.translated` 会把两句译文拼在一起——不仅字幕错位，TTS 也会串句。

**边界**

- 缓存只发生在「上一句已句终、最后一条译文仍未返回」的窗口内，正常情况窗口约几十到几百毫秒；ASR 通道自带背压，缓存不会无限增长。
- 普通模式（未启用翻译）不进入该分支，行为与既有语义完全一致。
- 该缓存只保证顺序，不改变「句终必须等最后一条译文」的屏障语义（D25）。
